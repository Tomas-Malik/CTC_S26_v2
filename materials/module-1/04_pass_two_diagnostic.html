Pass Two — Diagnostic Guide

The fork between structuring first and generating first, and the three checks for a structure-first attempt.

For facilitator use, and/or adapted into on-screen guidance if self-directed.

The task as given to the learner

Prompt to learners

“Same messy inputs as before. But now imagine the template from Pass One never existed — you’re brand new to this role, nobody left you an example, and you don’t actually know what Dana wants to see in a report like this. Use your AI assistant to help you figure out what should even go in this report — before you generate it.”

The instruction deliberately does not say “have a conversation first, then generate.” That’s the actual thing being tested: will the learner structure first, or will they default to the Pass One muscle memory and just generate immediately? Both are realistic; the lesson works either way, but the diagnostic differs.

The fork: did they structure first, or generate first?

Generated first

Not a failure to call out harshly — it’s the single most useful teachable moment in the whole module, because it’s exactly what most people will do under real deadline pressure. Likely result: a generic, template-shaped report full of plausible-sounding section headers (“Summary / Key Metrics / Challenges / Next Steps”) but where the content sorted into those headers is shakier than Pass One’s, because nobody — human or AI — actually decided what mattered to Dana specifically. It will look like a report. It may not be a useful report.

Diagnostic question: “Does this look like a report, or does it tell Dana what she actually needs to know? If you handed this to her with no other context, would she know what needs her attention?” Most learners will, on reflection, recognize the gap themselves rather than needing to be told.

Then: have them go back and run the structuring conversation (see below) before regenerating, and compare the two outputs side by side. The comparison is the lesson, not a lecture about it.

Structured first

Good — check the structuring conversation itself, not just the eventual report. Three things worth checking:

  1. Did they tell AI what Dana cares about, or did they ask AI to guess? “What sections should a nonprofit program report have” gets a generic, context-free answer. Better: “Dana is the program director, this goes in a board packet, she’s mainly scanning for anything that needs her decision or attention versus routine good news.”
  2. Did the structure leave room for “I don’t know yet”, not just “wins” and “metrics”? A common failure is a structure that’s all positive-framing with nowhere for the Denise situation or the placement correction to honestly live.
  3. Did they sanity-check the structure against the actual messy data before generating, or pick a structure in the abstract and hope it fit? Best practice: paste in the messy inputs as part of the structuring conversation, before generating.

What “good” looks like here, in general terms

There is no single right structure — that’s the point of this pass, and worth saying explicitly to the group so nobody assumes they got it “wrong” for landing somewhere different. But a structure that’s working well will usually:

  • Have somewhere for things that are good news, separate from things that need attention or a decision — because conflating them is how urgent things get missed.
  • Have somewhere for genuine uncertainty (the Denise situation, the corrected placement number, the unconfirmed rumor) that doesn’t force false resolution.
  • Reflect who’s reading it and why, not just “what sections does a report usually have.”

If a learner’s structure does all three but looks nothing like Pass One’s template — that’s success, not a deviation to correct.

Facilitator / guided-diagnosis flow

  1. Ask first, before looking at anything: “Did you have a back-and-forth with the AI about structure, or did you ask it to write the report directly?” Self-report, not inspection — this builds the habit of noticing your own process, which is the actual transferable skill.
  2. Walk through the three structuring-conversation checks above if they structured first; or run the compare-after-the-fact exercise if they didn’t.
  3. Close with the naming moment: “When there’s no example to anchor to, the AI can still help — but only if you treat it as a thinking partner on the structure before asking it to fill that structure in. Skipping straight to generation isn’t wrong, it’s just usually slower in the end, because you end up fixing structure and content at the same time instead of one at a time.”

A starter structuring-conversation opener

A direction, not a script — use if a learner doesn’t know how to start the structuring conversation at all.

Direction to nudge toward

“I need to write a monthly report for my manager, but I don’t have a template to work from. Before we write anything, help me think through: given that this goes to a nonprofit program director who’s mainly scanning for things that need her attention or a decision versus routine good news, what categories or sections would actually serve that? I’ll paste in what I actually have to report on once we’ve got a structure, so we can check it holds up against the real material.”

Same caveat as Pass One: this is a direction to nudge toward, not a model answer to hand over verbatim.
